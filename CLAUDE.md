# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Run from source: `pip install websocket-client "pillow>=10.1" && python Tickoshi.py` (Python 3.10+; Linux also needs `python3-tk`)
- Build Windows EXE: `BUILD.bat` → `dist\Tickoshi.exe` (PyInstaller `--onefile --windowed`; auto-installs pyinstaller, pillow, websocket-client — pillow unconditionally, so an older one is upgraded to the 10.1 the font fallback needs; kills a running Tickoshi.exe first)
- Build Linux binary: `./BUILD.sh` → `dist/Tickoshi` plus a `~/.local/share/applications/tickoshi.desktop` launcher
- Build macOS .app: `./BUILD.command` → `dist/Tickoshi.app` (ad-hoc signed via `codesign --sign -`, no Apple Developer ID) plus `dist/Tickoshi-macos.zip` (via `ditto`) for release upload. First launch still trips Gatekeeper — right-click → Open or `xattr -d com.apple.quarantine`. Also installs/bundles `certifi`: on macOS Python's OpenSSL can't read the system Keychain, so a darwin-gated block at the top of `Tickoshi.py` points `SSL_CERT_FILE` at certifi's bundle when the default trust store is empty — without it every HTTPS/WSS fetch fails `CERTIFICATE_VERIFY_FAILED`. `certifi` is macOS-only and explicitly `--exclude-module`d in `BUILD.bat`/`BUILD.sh`.
- No test suite, linter, or formatter is configured. There is no `requirements.txt` — the two runtime dependencies (`websocket-client`, `pillow`) are installed manually or by the build scripts.

## Layout

- `Tickoshi.py` — the whole application.
- `BUILD.bat` / `BUILD.sh` / `BUILD.command` — stay in the top folder so they can be double-clicked; each runs from its own directory and refers to `assets/` by relative path.
- `assets/` — app icons (`Tickoshi.ico` for the Windows EXE, `Tickoshi.icns` for the macOS app, `Tickoshi.png` for the Linux launcher and the README) and the README screenshots. Nothing in here is loaded by the app at runtime.
- `docs/` — the support page served by GitHub Pages. It must stay named `docs` at the top level (Pages only offers `/` or `/docs`) and cannot reach files outside itself, which is why it carries its own copy of the icon.
- `.github/FUNDING.yml` — the Sponsor button.

## Architecture

The entire application lives in `Tickoshi.py`. It is a frameless Tkinter widget that composites custom `Canvas` "panels" into a single always-on-top window. Tk only hosts and lays out the panels; every pixel of a tile is painted with Pillow.

### Rendering model
Tk's canvas has no gradients, alpha, blur or antialiasing, so the "Render engine" section near the top of the file draws each tile as a Pillow image at `_SS`x size and scales it down. A tile is a cached pair from `_card_layers` — a base (shadow, rim, card body) and an overlay (glass highlight, edge lighting, flap seam) — with the text drawn between the two by `_draw_text`. Rim, glow and shadow must fade out inside the tile's own `pad`, or the canvas edge cuts them and a seam shows between tiles. `_FACE_RGB` must stay equal to `C_FACE` for the same reason. Don't tint an area with the accent at low opacity over the black card: a 10% tint behind the stat labels turned Bitcoin orange into brown. Use the accent at full strength or not at all.

Each visible cell is a subclass of `_ImagePanel` (a `tk.Canvas` holding one `PhotoImage`, which it must keep a reference to):
- `DigitPanel` — one digit card; `_flip` animates a split-flap fold over `DRUM_STEPS` frames of `DRUM_MS` by compositing the cached old and new card images in `_flip_frame`.
- `SignPanel` — the currency symbol card.
- `LabelPanel` — the BTC / currency card.
- `FeeBlock` — the `[ LABEL | value unit ]` tile used for the three fee tiles and every other stat (Sats, Height, Halving, Hashrate, Mempool, …). Values with a leading sign are tinted green/red. `_fit_font` shrinks text that would overflow, since DejaVu and the fallback face run wider than Segoe UI.

`NewsTicker` is the one panel that moves continuously. All headlines are rendered once into a single strip image (`_render_news_strip`, one headline at a time — a supersampled image of the whole strip would be tens of megapixels) that carries the card's own background; the strip is shown twice end to end and scrolling is only `canvas.coords` on those two items. Two slices cut from the card sit above them at each end so text slides under the rim. Don't re-render per frame.

The chassis rim is one window-sized image (`_frame_layers` + `_render_frame`); the price flash repaints it through `PULSE_LEVELS` quantised glow levels rather than on every timer step. The **Finish** setting (`FINISHES`: Gloss / Matte) is passed to every render helper and is part of every cache key. Fonts are loaded by file in `_load_font` from the per-platform `_FONT_FILES` list, falling back to Pillow's built-in face. Pillow never substitutes a font for a missing glyph the way Tk did, so `_load_font` takes the text and skips faces that can't draw it — pass the text whenever it may hold a currency sign. `_build_ui` clears `_render_cache` on every rebuild: left to accumulate across sizes, colours and finishes it reached 200 MB, against about 13 MB for one configuration.

The top-level `Tickoshi(tk.Tk)` class owns layout, the right-click menu, config persistence, drag/lock behavior, and the "accordion" resize logic that adapts the window width to the current digit count and which optional tiles are enabled. `_layout_rows(modules)` is the single definition of how the tiles under the price are arranged: half-width tiles pair two to a row, and a full-row tile (`FULL_ROW_MODULES`: News, Fees) is placed at once *without* ending the pair in progress, so a half-width tile waiting for a partner drops below it. At most one tile is ever alone (the last half-width one when their number is odd), and it stays above any full-row tiles listed after it. `_build_ui` builds exactly those rows, the window height is their count, and `_move_module` reorders in terms of them; never re-derive the rule somewhere else, a second copy that disagreed is what once made the window crop its own content. A full-row tile moves by whole rows, because a list position between the two tiles of a pair is not a place on screen. A left-drag moves the window from anywhere; resting the mouse on a tile for `HOLD_MS` first turns the drag into a reorder (`_begin_reorder` / `_reorder_over` / `_move_module`), marked with `_ImagePanel.set_mark`. The drag handlers run twice per event (widget binding plus the inherited toplevel binding) and must stay safe to repeat; `_build_ui` calls `_end_reorder()` because a rebuild destroys the tiles a gesture refers to. Panel dimensions scale from `BASE_PANEL_W/H/FS/R` by `self._scale`. That factor, also the `scale` value in the config, is *not* the percentage the user sees: 100% is `SIZE_UNIT` (0.6) of the base dimensions, converted with `_scale_to_pct` / `_pct_to_scale`. Keeping the stored value as the raw factor is what left existing users' sizes unchanged when the percentages were recalibrated. Sizes run from `SIZE_MIN` to `SIZE_MAX` percent; don't lower the floor without looking at it, because below roughly 65% the `max(...)` pixel clamps on tile and font sizes take over, the window stops shrinking and values are squeezed out: the Size menu offers `SIZE_PRESETS`, and Ctrl + mouse wheel steps by `SIZE_STEP` (debounced, since a rebuild re-renders every tile). On Windows the area outside the chassis' rounded outline is painted in `_CORNER_KEY` and made see-through with `-transparentcolor`; other platforms have no colour key, so their corners stay face-coloured.

### Data sources and threading
Network I/O runs on background threads and hands results to the Tk main loop via a `queue.Queue` polled on the Tk timer — never touch Tk widgets from a worker thread.
- Price: CoinGecko primary, Binance fallback (`_fetch_all_prices`). Polled on the user's refresh interval (1/5/15/30/60 min; `REFRESH_OPTIONS`) — but a cycle that fetched no live price reschedules on a short escalating backoff instead (`FETCH_RETRY_MIN_S`..`FETCH_RETRY_MAX_S`, see `_next_fetch_delay`), so one rate limit doesn't blank the price for a whole interval. Success means a usable quote for the currency on screen, not merely an HTTP 200: CoinGecko answers 200 with an error-shaped body when throttling, and treating that as success skipped the fallback entirely. `CURRENCIES` carries `None` for pairs Binance has delisted (GBP, RUB) — requesting them is a guaranteed `-1121 Invalid symbol`. The CoinGecko call also carries `include_24hr_change=true`, so the 24h move for every currency arrives in the same request — Binance has no equivalent, so the 24h tile reads `--` whenever the fallback supplied the price.
- Block height: `blockchain.info` (`_fetch_block_height`). Halving days are computed by `calc_halving_days`, which derives the next halving from the height via `HALVING_INTERVAL` — don't reintroduce a hardcoded next-halving constant, it turns the tile into `--` forever once that block is mined.
- Hashrate: mempool.space mining REST endpoint (`_fetch_hashrate`).
- Fees, mempool size, difficulty retarget and block height/age: one persistent WebSocket to `wss://mempool.space/api/v1/ws` via `websocket-client`. The socket pushes more than the app once read — `da` carries `difficultyChange`/`remainingBlocks` beside the hashrate, and `blocks` (an array on connect) plus `block` (one per new block) carry height and timestamp. Height from the socket lands the moment a block is mined; `_fetch_block_height` stays as the HTTP fallback and never rolls the height backwards. Lifecycle is managed by the module-level `_ws_start` / `_ws_stop` / `_ws_run` and the `_ws_on_*` callbacks. `_ws_run` takes a generation token so a run winding down from an earlier `_ws_stop()` retires instead of blocking a restart — checking only `is_alive()` there left the feed dead for the session when a tile was toggled off and straight back on. Reconnect backoff resets after a connection holds for `WS_STABLE_S`.

One invariant holds the loop together, and both halves of it were bugs before: the queued result is what arms the next cycle, so `_worker` posts it from a `finally` and `_on_fetch_done` reschedules from a `finally`. Never make either conditional on success — the result poller swallows what is raised in the callback, so one exception used to stop the widget refreshing for the rest of the session with nothing in the log.

There is a second, slower loop, `_aux_loop` / `_on_aux_done`, with its own generation counter and the same `finally` invariant. It feeds the tiles in `AUX_MODULES` every `AUX_REFRESH_S` (or `AUX_RETRY_S` after a round that got nothing), regardless of the price interval, and it stops itself when none of those tiles is on — every place that toggles a tile or changes currency calls `_aux_loop()` to restart it. It is separate so headlines don't go stale on a 60-minute price interval and so nothing in it can reach the price loop.
- News: `_fetch_news` reads the RSS feeds in `NEWS_FEEDS` and merges them newest first; one feed failing must not empty the ticker. `_parse_feed` handles RSS 2.0 and Atom. Feed content is untrusted and a link ends up in `webbrowser.open`, so `_parse_feed` drops anything that is not `http(s)://` and `NewsTicker.open_at` checks again — keep both.
- Price chart and ATH: one CoinGecko `/coins/markets` request with `sparkline=true` (`_fetch_market_extras`); the last 24 hourly points are the chart.
- Fear & Greed: alternative.me (`_fetch_fear_greed`), refetched at most every `FNG_REFRESH_S`.
- New-block flash: `_ws_on_message` bumps `_network_cache["block_seq"]` for a lone `block` push only — the `blocks` array sent on connect is history. The one-second tick (`_check_new_block`) flashes the rim when the number moves, unless a price flash is running. `_needs_ws()` therefore includes the flash, and also Block Age / Difficulty / Height, whose data arrives only on the socket.

When adding a new data source, follow the same pattern: fetch on a worker thread, push into the queue, render on the Tk tick.

### Start at login
`autostart_enabled()` / `set_autostart()` register the app for login: a `Run` registry value on Windows, a LaunchAgent plist on macOS, an autostart `.desktop` on Linux. The state is read back from the OS every time the menu opens rather than mirrored into our config, so an entry removed behind the app's back shows as off. `_launch_command()` returns the executable alone when frozen (PyInstaller sets `sys.frozen`) and interpreter-plus-script otherwise.

### Packaging note
All three scripts invoke pip and PyInstaller as `python -m pip` / `python -m PyInstaller`, never by console-script name: a pip install puts `pyinstaller.exe` in Python's `Scripts` directory (or `~/.local/bin`), which is not on `PATH` by default, so calling it by name fails with "not recognized" even though the package installed fine. Keep that form when editing them.

`BUILD.bat` / `BUILD.sh` / `BUILD.command` aggressively exclude heavy stdlib/third-party modules (numpy, pandas, matplotlib, smtplib, http.server, etc.) to keep the onefile binary small. If you add an import that transitively pulls one of these in, update the exclude list in all three scripts or the build will ship a much larger binary. All three pass `--hidden-import PIL._tkinter_finder`: `ImageTk` loads it dynamically and a frozen build without it fails the first time a tile is drawn.
